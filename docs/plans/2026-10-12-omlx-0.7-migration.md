# oMLX 0.7 Migration Plan

- Date: 2026-10-12
- Status: draft
- Reference: https://github.com/jundot/omlx/issues/3730 (`auth.allow_unauthenticated_inference`)
- Scope: migrate inference nodes msm1/msm2/msm3/msm4 from oMLX 0.6.4 to pinned oMLX 0.7.0

## 1. Background

On 2026-10-12, `make bootstrap msm1` upgraded oMLX from 0.6.4 to 0.7.1.dev1
(`DEFAULT_OMLX_TOOL_SPEC` tracks git main). oMLX 0.7 rejects servers that bind a
non-loopback host without an API key:

```
Configuration error: API key verification cannot be skipped when binding to a non-loopback host (0.0.0.0).
```

The launchd job crash-looped (`runs = 169`, `last exit code = 1`), health checks
got connection refused, and `cluster prepare` failed at the strict restart step.

Current fleet state:

| Node | oMLX | Daemon state |
|------|------|--------------|
| msm1 | 0.7.1.dev1 | crash loop (broken; version itself is fine — config is missing) |
| msm2/msm3/msm4 | 0.6.4 | running |
| studio (cache) | no oMLX daemon | unaffected (downloader flows already pass `--api-key`) |

## 2. oMLX 0.7 auth model (verified in source)

Two endpoint tiers plus one always-open route decide everything:

| Tier | Endpoints | Guard |
|------|-----------|-------|
| Inference | `/v1/models`, `/v1/chat/completions`, embeddings, rerank, audio, MCP, websearch | `verify_inference_api_key` |
| Management | `/api/status`, `/v1/models/status`, load/unload, `/admin/*` | `verify_api_key` |
| Open | `/health` | none |

Key facts (omlx v0.7.0 source):

- `omlx/server.py` `verify_api_key`: without a configured key, requests succeed
  only on loopback binds. `auth.skip_api_key_verification` is honored on
  loopback binds only. Accepts `Authorization: Bearer <key>` or `X-Api-Key`.
- `omlx/server.py` `verify_inference_api_key`: returns True when
  `auth.allow_unauthenticated_inference` is true (new in 0.7, issue #3730) —
  open inference without weakening management auth.
- Key sources all converge on `settings.auth.api_key` (fed to `init_server`,
  `omlx/cli.py:447`): `--api-key` flag, `OMLX_API_KEY` env var
  (`settings.py:1269`), or `settings.json`.
- `settings.json` lives at `~/.omlx/settings.json` (daemon `HOME` is the node
  user's home), written 0600 via temp-file rename. At startup oMLX adds
  `auth.allow_unauthenticated_inference: false` if absent
  (`ensure_inference_auth_setting`), preserving an existing value.
- Startup guard `network_auth_error` (`omlx/utils/network.py:142`) rejects
  non-loopback binds without a key — the exact error msm1 hit.
- Removed flags: `--max-model-memory`, `--max-process-memory`. Replacement:
  `--memory-guard {off,safe,balanced,aggressive}` (guard defaults to on) and
  `--memory-guard-gb N` (sets the custom ceiling).

## 3. Target posture and decisions

1. **Inference stays open on the LAN** (same effective posture as 0.6.4):
   set `auth.allow_unauthenticated_inference: true` on every inference node.
   Inference is still authenticated — at the TF layer (edge keys at TF edge →
   Olla); oMLX itself intentionally does not re-authenticate inference.
   Olla, TF edge, edge clients, and Hindsight need no changes. This is still
   strictly stronger than 0.6.4, where the entire API (including admin) was
   open on `0.0.0.0`.
2. **One cluster management key**: `OMLX_API_KEY` in the management host `.env`
   (repo convention: secrets in `.env`), shared by all msm inference nodes and
   distributed by TF during prepare. Protects management endpoints on all
   nodes. Per-client sub-keys (`auth.sub_keys`) are explicitly out of scope.
3. **Key delivery via settings.json, not the plist**: during prepare, TF
   merge-edits `~/.omlx/settings.json` on each node
   (`auth.api_key`, `auth.allow_unauthenticated_inference: true`) over SSH as
   the node user. Rejected alternative: `--api-key` in the plist —
   `/Library/LaunchDaemons/*.plist` is world-readable 644, and settings.json is
   the oMLX-native home that must carry the opt-in flag anyway (one file, one
   write, 0600 perms).
4. **Bootstrap installs the latest release tag, not git main**:
   `cluster prepare` resolves the latest published tag via the GitHub releases
   API (`/repos/jundot/omlx/releases/latest` — `v0.7.1.dev1` today) and
   installs `git+https://github.com/jundot/omlx.git@<tag>`. Plain
   `git+...omlx.git` tracks git **main**, which drifts ahead of releases —
   that was the original msm1 upgrade trigger. No static pin; resolution is
   fail-fast (prepare aborts if the API is unreachable).
5. **`trusted_network: true` stays** as the operator attestation that a node
   may serve inference on the LAN (it maps to the opt-in flag above). It no
   longer suppresses an oMLX-side warning because 0.7 enforces auth itself.
6. **Fail fast**: prepare errors out when a runtime binds non-loopback and
   `OMLX_API_KEY` is unset — mirroring oMLX's own `network_auth_error`.

## 4. Work items

### Phase 1 — thunder-forge code changes

1. `cluster/omlx.py`
   - `check_omlx_health(..., api_key: str | None = None)` and
     `smoke_omlx_chat(..., api_key=...)`: send `Authorization: Bearer` when a
     key is present (needed for `/v1/models/status` and `/api/status`; harmless
     elsewhere). When the argument is omitted, fall back to the
     `OMLX_API_KEY` process env so every existing call site is covered.
     Thread through `_wait_for_omlx_health` and the daemon restart paths.
   - New `ensure_omlx_auth_settings(node, api_key=...)`: remote merge-write of
     `~/.omlx/settings.json` (see item 3). The merge also forces
     `auth.skip_api_key_verification: false` — 0.6.x nodes carry that legacy
     flag set to `true` (oMLX UI era), and the 0.7 startup guard rejects it on
     non-loopback binds **before** it ever looks at the API key. That was the
     real trigger of the original msm1 crash loop, not a missing key.
   - Follow-up (not in this change): replace the dead
     `max_model_memory` / `max_process_memory` runtime fields (removed flags in
     0.7) with `memory_guard_gb` → `--memory-guard-gb`; no node sets them
     today, so nothing breaks by leaving them.
   - `check_omlx_health(..., api_key: str | None = None)` and
     `smoke_omlx_chat(..., api_key=...)`: send `Authorization: Bearer` when a
     key is present (needed for `/v1/models/status` and `/api/status`; harmless
     elsewhere). Thread through `_wait_for_omlx_health`.
2. `cluster/config.py`
   - Follow-up: add `memory_guard_gb` to `NodeRuntime` + tfconfig parsing (the
     tfconfig comments already reference it).
   - Prepare-time fail fast (in `cli.py`, where the env is loaded): non-loopback
     runtime bind requires `trusted_network: true` **and** a resolvable
     `OMLX_API_KEY` at prepare time.
3. Settings bootstrap step (new, `cluster/omlx.py`)
   - Remote python heredoc (pattern: `remote_cache.py`) run as the node user
     before daemon setup: load `~/.omlx/settings.json`, set
     `auth.api_key` / `auth.allow_unauthenticated_inference: true`, write
     atomically, preserve all other keys, 0600. Idempotent.
4. `cli.py`
   - Load the repo `.env` in `_load_config()` so every probing command sees
     `OMLX_API_KEY` without per-command plumbing.
   - `cluster prepare` inference loop: fail fast when a node binds non-loopback
     and `OMLX_API_KEY` is unset; run the settings bootstrap step before daemon
     setup.
5. Tests
   - settings-merge script (idempotency, key preservation, 0600).
   - health probes with/without key (mock transport).
   - lint: non-loopback + missing key fails; `--memory-guard-gb` mapping.
6. Hardening (small): the daemon setup script's
   `launchctl print | grep "job state = running"` accepted a transient state
   during the incident. Retry the probe over ~5 s before declaring success.

### Phase 2 — staged rollout (one node at a time, msm1 first)

Prereq: generate `OMLX_API_KEY=$(openssl rand -hex 32)` into `.env`.

1. `make bootstrap msm1` (with Phase 1 code): keeps 0.7.1.dev1, writes
   settings.json (`auth.api_key` + `auth.allow_unauthenticated_inference: true`),
   restarts daemon.
2. Verify msm1:
   - `launchctl print system/com.thunder-forge.omlx-8018` → running, exit 0
   - `curl http://msm1-wifi.lan:8018/health` → 200 (no auth)
   - `curl .../v1/models` → 200 (no auth, inference tier open)
   - `curl .../v1/models/status` → 401 without key, 200 with Bearer key
   - `curl .../v1/chat/completions` no auth → 200
   - `make smoke msm1`, `make status msm1` (model_statuses populated)
3. Roll to msm2, msm3 the same way.
4. msm4 last (per tfconfig rollout note): after step 3 is green, verify the
   Hindsight path (`make edge-usage` / edge smoke for the hindsight client).
   Hindsight reaches models through TF edge → Olla, so no client change is
   expected; confirm before and after.
5. Cache hub studio: no daemon, nothing to migrate; downloader flows already
   pass `--api-key`.

### Phase 3 — cleanup

- CHANGELOG entry; consider ADR-0003 documenting the auth posture decision
  (open LAN inference, keyed management) alongside ADR-0001/0002.
- Revisit `trusted_network` naming in a later pass (now means "opt in to
  unauthenticated LAN inference"); do not rename in this migration.

## 5. Rollback

Emergency escape hatch only: pin `DEFAULT_OMLX_TOOL_SPEC` to `@v0.6.4` and
`make bootstrap <node>` — uv downgrades in place, 0.6.4 ignores the unknown
settings.json keys (`AuthSettings.from_dict` reads known keys only), and the
daemon returns to the previous behavior. The settings.json edits can stay in
place. Not part of the normal flow; the default stays upgrade-to-latest.

## 6. Out of scope

- Per-client oMLX sub-keys and locking down inference traffic (would require
  Olla endpoint `auth:` blocks — supported since Olla endpoint-auth — plus key
  distribution to every LAN client). Revisit when direct LAN access beyond TF
  edge/Olla needs to be closed.
- `memory_guard_gb` runtime field mapping to `--memory-guard-gb` (no node
  sets the removed `--max-model-memory` / `--max-process-memory` flags today).
